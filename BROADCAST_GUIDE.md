# 📢 Руководство по массовой рассылке

## Обзор

Система массовой рассылки позволяет администраторам отправлять сообщения всем зарегистрированным участникам бота. Рассылка учитывает лимиты Telegram API и использует 3 воркера Celery для параллельной обработки.

## Основные возможности

- ✅ **Текстовые сообщения** с поддержкой Markdown форматирования
- ✅ **Фото с подписью** для визуальных объявлений
- ✅ **Интерактивный интерфейс** с предпросмотром
- ✅ **Автоматическое соблюдение лимитов** Telegram API (18 сообщений/сек)
- ✅ **Мониторинг прогресса** в реальном времени
- ✅ **Детальная статистика** по завершению
- ✅ **Повторные попытки** при ошибках (до 3 раз)

## Доступные команды

### `/broadcast` - Запуск массовой рассылки

Интерактивная команда для создания и отправки рассылки всем участникам.

**Процесс:**
1. Выбор типа рассылки (текст или фото)
2. Ввод содержимого
3. Предпросмотр
4. Подтверждение (с возможностью изменить или отменить) и отправка

**Пример использования:**
```
/broadcast
→ Выбираешь тип → Вводишь текст/загружаешь фото → Подтверждаешь
```

### `/broadcast_test` - Тестовая рассылка

Отправляет сообщение только тебе (администратору) для проверки форматирования.

**Использование:**
```
/broadcast_test Привет! Это **тестовое** сообщение с *форматированием*.
```

## Типы рассылок

### 1. Текстовая рассылка

**Характеристики:**
- Максимальная длина: 4096 символов
- Поддержка Markdown форматирования
- Быстрая доставка

**Markdown форматирование:**
- `**жирный**` → **жирный**
- `*курсив*` → *курсив*
- `` `код` `` → `код`
- `[ссылка](https://example.com)` → [ссылка](https://example.com)

**Пример:**
```markdown
🎉 **ВАЖНОЕ ОБЪЯВЛЕНИЕ!**

Уважаемые участники!

📅 **Дата мероприятия:** 15 декабря 2024
🕐 **Время:** 18:00
📍 **Место:** Главный корпус

⚠️ *Не забудьте взять билеты!*
```

### 2. Фото с подписью

**Характеристики:**
- Поддержка JPG, PNG
- Максимальная длина подписи: 1024 символа
- Поддержка Markdown в подписи
- Более привлекательно для визуальных объявлений

**Пример подписи:**
```markdown
🎊 **АФИША МЕРОПРИЯТИЯ**

📅 15 декабря | 🕐 18:00
📍 Главный корпус

✨ Будет интересно!
```

## Технические детали

### Производительность

- **Скорость рассылки:** ~18 сообщений/секунду (ограничение Telegram API)
- **Воркеры:** 3 параллельных процесса Celery
- **Rate Limiter:** Распределенный через Redis (синхронизация между воркерами)

### Расчет времени рассылки

```
Время (сек) = Количество получателей / 18
```

**Примеры:**
- 100 пользователей: ~6 секунд
- 500 пользователей: ~28 секунд
- 1000 пользователей: ~56 секунд
- 3500 пользователей: ~3.2 минуты

### Обработка ошибок

Система автоматически обрабатывает ошибки:

1. **Пользователь заблокировал бота:** Пропускается
2. **Telegram ID не найден:** Пропускается
3. **Временная ошибка сети:** Повторная попытка (до 3 раз с интервалом 30 сек)
4. **Превышен лимит:** Автоматическая задержка через rate limiter

### Мониторинг прогресса

Система отправляет обновления прогресса:
- **Каждые 50 сообщений** - промежуточная статистика
- **По завершению** - финальный отчет

**Пример обновления:**
```
📊 Прогресс рассылки

✅ Отправлено (примерно): 150 / 500 (30.0%)
⏳ Осталось: 350
⏱ Примерное время: ~19 сек
```

**Финальный отчет:**
```
✅ Рассылка завершена!

📊 Статистика:
• Всего получателей: 500
• ⏱ Время выполнения: 0 мин 28 сек
• 📈 Скорость: ~17.8 сообщений/мин

💡 Примечание: Для точной статистики (успешных/ошибок) проверь логи воркеров.
```

## Требования

### Переменные окружения (.env)

```bash
# Telegram Bot Token
BOT_TOKEN=your_bot_token

# Admin IDs (разделенные запятыми)
ADMIN_IDS=123456789,987654321

# Redis для Celery и Rate Limiter
REDIS_BROKER_URL=redis://localhost:6379/1

# База данных
DATABASE_URL=postgresql+asyncpg://user:pass@localhost/dbname
```

### Запуск Celery воркеров

Для работы рассылки нужны запущенные Celery воркеры:

```bash
# 3 воркера (рекомендуется)
celery -A tasks worker --loglevel=info --concurrency=3
```

### Мониторинг Celery (опционально)

```bash
# Flower - веб-интерфейс для мониторинга
celery -A tasks flower
# Доступ: http://localhost:5555
```

## Безопасность

### Ограничения доступа

- Только администраторы (указанные в `ADMIN_IDS`) могут использовать команды рассылки
- Проверка прав происходит на каждом шаге

### Проверки перед отправкой

1. **Получатели:** Только пользователи с:
   - `telegram_id IS NOT NULL`
   - `ticket_cancelled = FALSE`

2. **Контент:**
   - Проверка длины текста (4096 символов)
   - Проверка длины подписи (1024 символа)
   - Валидация файлов

3. **Предпросмотр:** Обязательный просмотр перед отправкой

## Частые вопросы (FAQ)

### Q: Можно ли отменить рассылку после запуска?

**A:** Нет. После подтверждения рассылка запускается автоматически. Используй `/broadcast_test` для проверки.

### Q: Что происходит если пользователь заблокировал бота?

**A:** Задача пропускает такого пользователя и продолжает работу. Это не считается ошибкой.

### Q: Как узнать точное количество успешных/неудачных отправок?

**A:** Проверь логи Celery воркеров:
```bash
tail -f celery.log | grep "Broadcast"
```

### Q: Можно ли отправлять видео или другие типы медиа?

**A:** В текущей версии поддерживаются только текст и фото. Для других типов нужна доработка.

### Q: Как увеличить скорость рассылки?

**A:** Нельзя. Скорость ограничена Telegram API (20 запросов/сек). Мы используем 18 для безопасности.

### Q: Что делать если рассылка "зависла"?

**A:** 
1. Проверь статус Celery воркеров: `celery -A tasks inspect active`
2. Проверь логи: `tail -f celery.log`
3. Перезапусти воркеры если нужно

### Q: Сколько можно сделать рассылок подряд?

**A:** Неограниченно, но учитывай что Telegram может ограничить бота при частых рассылках большому количеству пользователей.

## Архитектура

### Схема работы

```
Admin → /broadcast → FSM States → Confirmation
                                       ↓
                              Celery mass_broadcast_task
                                       ↓
                    [Worker 1]  [Worker 2]  [Worker 3]
                         ↓           ↓           ↓
                    Redis Rate Limiter (18 msg/sec)
                         ↓           ↓           ↓
                    send_broadcast_message_task
                         ↓           ↓           ↓
                      Telegram API
                         ↓           ↓           ↓
                       Users
```

### Компоненты

1. **bot/broadcast_handlers.py** - Обработчики команд и FSM логика
2. **tasks.py** - Celery задачи для рассылки
3. **bot/sender.py** - Низкоуровневая отправка через Telegram API
4. **Redis** - Брокер задач и rate limiter
5. **PostgreSQL** - Хранение данных пользователей

## Устранение неполадок

### Проблема: Воркеры не запускаются

**Решение:**
```bash
# Проверь Redis
redis-cli ping
# Должен вернуть: PONG

# Проверь переменные окружения
echo $REDIS_BROKER_URL

# Запусти воркеры с debug логами
celery -A tasks worker --loglevel=debug
```

### Проблема: Рассылка не отправляется

**Решение:**
1. Проверь что воркеры запущены: `celery -A tasks inspect active`
2. Проверь Redis: `redis-cli ping`
3. Проверь логи: `tail -f celery.log`
4. Проверь BOT_TOKEN в .env

### Проблема: Медленная рассылка

**Решение:**
- Это нормально! Telegram ограничивает скорость до 20 msg/sec
- Мы используем 18 msg/sec для безопасности
- Для 3500 пользователей ожидается ~3.2 минуты

### Проблема: Ошибки "Flood wait"

**Решение:**
- Rate limiter должен предотвращать это
- Проверь что Redis работает корректно
- Уменьши concurrency воркеров до 2: `--concurrency=2`

## Поддержка

При возникновении проблем:

1. **Проверь логи:**
   - `tail -f bot.log` (бот)
   - `tail -f celery.log` (воркеры)

2. **Проверь сервисы:**
   - Redis: `redis-cli ping`
   - PostgreSQL: `psql -c "SELECT 1"`
   - Celery: `celery -A tasks inspect ping`

3. **Документация:**
