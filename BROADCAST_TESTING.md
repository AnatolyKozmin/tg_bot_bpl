# 🧪 Тестирование системы массовой рассылки

## Быстрая проверка системы

### 1. Проверка всех компонентов

```bash
# Redis
redis-cli ping
# Ожидаемый результат: PONG

# PostgreSQL
psql -U postgres -d event_bot -c "SELECT COUNT(*) FROM surveys;"
# Ожидаемый результат: количество пользователей

# Celery воркеры
celery -A tasks inspect ping
# Ожидаемый результат: список активных воркеров
```

### 2. Тестовая рассылка

Самый простой способ проверить систему:

```
/broadcast_test Это **тестовое** сообщение!
```

Сообщение придет только тебе (админу).

## Пошаговое тестирование

### Тест 1: Простое текстовое сообщение

**Цель:** Проверить базовую функциональность

1. Отправь в бот:
   ```
   /broadcast
   ```

2. Выбери "📝 Текстовое сообщение"

3. Введи:
   ```
   🧪 **ТЕСТ**
   
   Это тестовая рассылка.
   Проверка системы.
   ```

4. Подтверди отправку

5. **Ожидаемый результат:**
   - Все пользователи получат сообщение
   - В логах `celery.log` появятся записи "✅ Broadcast sent"
   - Flower покажет выполненные задачи

### Тест 2: Сообщение с форматированием

**Цель:** Проверить Markdown форматирование

```markdown
🎉 **Заголовок жирным**

Это обычный текст с *курсивом*.

Список:
• Пункт 1
• Пункт 2

`Код в строке`

[Ссылка](https://example.com)
```

**Проверь:** Форматирование должно корректно отображаться

### Тест 3: Фото с подписью

**Цель:** Проверить рассылку изображений

1. `/broadcast` → "🖼 Фото с подписью"
2. Загрузи любое изображение (JPG/PNG)
3. Введи подпись:
   ```markdown
   📸 **Тестовое фото**
   
   Проверка рассылки изображений
   ```
4. Подтверди

**Ожидаемый результат:** Все получат фото с подписью

### Тест 4: Максимальная длина текста

**Цель:** Проверить ограничения Telegram

```markdown
# Создай текст длиной 4000+ символов
# Telegram лимит: 4096 символов для текста
```

**Ожидаемый результат:** 
- Если <4096 символов → отправляется
- Если >4096 символов → ошибка валидации

### Тест 5: Фото без подписи

**Цель:** Проверить опциональность подписи

1. `/broadcast` → "🖼 Фото с подписью"
2. Загрузи фото
3. Нажми "⏭ Без подписи"
4. Подтверди

**Ожидаемый результат:** Фото отправляется без текста

## Тестирование ошибок

### Тест: Пользователь заблокировал бота

**Создай тестового пользователя, заблокируй бота**

**Ожидаемый результат:** 
- Задача помечается как "failed" но не падает
- Другие пользователи получают сообщения
- В логах: "Failed to send broadcast" (но не критическая ошибка)

### Тест: Неверный Telegram ID

**Измени в БД telegram_id на несуществующий**

```sql
UPDATE surveys SET telegram_id = '999999999999' WHERE id = 1;
```

**Ожидаемый результат:**
- Ошибка "Chat not found"
- До 3 повторных попыток
- Остальные пользователи не затронуты

### Тест: Redis недоступен

**Остановка Redis во время рассылки**

```bash
# Linux
sudo systemctl stop redis

# Windows
# Закрой redis-server
```

**Ожидаемый результат:**
- Rate limiter переходит в fallback режим
- Рассылка продолжается (с фиксированной задержкой)
- В логах: "Rate limiter error: ... Using fallback delay"

### Тест: Celery воркеры упали

**Останови воркеры во время рассылки**

```bash
# Ctrl+C в окне с Celery
```

**Ожидаемый результат:**
- Задачи остаются в очереди Redis
- После перезапуска воркеров - продолжается обработка

## Тестирование производительности

### Измерение скорости рассылки

**Python скрипт для теста:**

```python
import time
from datetime import datetime

# Перед рассылкой
start_time = time.time()
print(f"Start: {datetime.now()}")

# Запусти /broadcast
# ... ожидай завершения ...

# После рассылки
end_time = time.time()
duration = end_time - start_time
messages_count = 500  # Замени на реальное количество

speed = messages_count / duration
print(f"End: {datetime.now()}")
print(f"Duration: {duration:.2f} seconds")
print(f"Speed: {speed:.2f} messages/second")
```

**Ожидаемая скорость:** 16-18 сообщений/секунду

## Частые проблемы при тестировании

### 1. Медленная рассылка

**Проблема:** Скорость <10 сообщений/сек

**Возможные причины:**
- Redis медленный (проверь latency: `redis-cli --latency`)
- Сеть медленная
- CPU перегружен

**Решение:**
- Оптимизируй Redis
- Увеличь ресурсы сервера

### 2. Ошибки "Connection pool is full"

**Проблема:** PostgreSQL не принимает соединения

**Решение:**
```python
# В db/session.py увеличь pool_size
pool_size=100,
max_overflow=200
```

### 3. Задачи "pending" но не выполняются

**Проблема:** Воркеры не берут задачи

**Решение:**
```bash
# Перезапусти воркеры
pkill -f celery
celery -A tasks worker --loglevel=info --concurrency=3
```

### 4. Rate limit ошибки

**Проблема:** "Too many requests" от Telegram

**Решение:**
- Rate limiter должен это предотвращать
- Проверь что Redis работает
- Уменьши `max_per_second` в `sender.py`:
  ```python
  TelegramRateLimiter(max_per_second=15)  # Было 18
  ```

## Автоматизированное тестирование

### Pytest тесты (будущее расширение)

```python
# tests/test_broadcast.py

import pytest
from tasks import send_broadcast_message_task

@pytest.mark.asyncio
async def test_broadcast_message():
    """Тест отправки одного сообщения"""
    result = send_broadcast_message_task.delay(
        user_id=1,
        telegram_id="123456789",
        message_text="Test message"
    )
    assert result.get(timeout=10)['status'] == 'success'

@pytest.mark.asyncio
async def test_broadcast_invalid_user():
    """Тест с несуществующим пользователем"""
    result = send_broadcast_message_task.delay(
        user_id=1,
        telegram_id="999999999",
        message_text="Test"
    )
    assert result.get(timeout=10)['status'] == 'error'
```
