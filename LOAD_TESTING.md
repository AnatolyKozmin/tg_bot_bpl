# 🔥 Нагрузочное тестирование бота

## 🎯 Зачем это нужно:

- Проверить, выдержит ли бот 200-500 одновременных регистраций
- Найти узкие места **ДО** реального ажиотажа
- Убедиться что оптимизации работают

---

## 🚀 Быстрый старт:

### 1. Установка зависимостей

**На сервере:**
```bash
cd ~/tg_bot_bpl
pip install faker  # Или через docker
docker-compose exec bot pip install faker
```

**Локально (для разработки):**
```bash
pip install faker aiohttp
```

### 2. Запуск тестов

Есть **3 режима** тестирования:

---

## 📊 Режим 1: Быстрая проверка (30 секунд)

**Что делает**: Проверяет все компоненты системы

```bash
# На сервере
docker-compose exec bot python load_test.py --mode quick

# Локально
python load_test.py --mode quick
```

**Результат:**
```
✅ PostgreSQL работает
✅ Redis работает  
✅ Выполнено 10 одновременных регистраций: 10 успешных
✅ Celery tasks доступны
```

---

## 🔒 Режим 3: Стресс-тест блокировок

**Что делает**: Тестирует `SELECT FOR UPDATE` (главное узкое место)

```bash
# 50 конкурентных запросов в течение 10 секунд
docker-compose exec bot python load_test.py --mode stress --concurrent 50 --duration 10

# Экстрим: 200 конкурентных запросов
docker-compose exec bot python load_test.py --mode stress --concurrent 200 --duration 20
```

## 📋 Полный сценарий тестирования:

### Перед открытием регистрации:

```bash
# 1. Быстрая проверка всех компонентов
docker-compose exec bot python load_test.py --mode quick

# 2. Тест на 100 пользователей (разогрев)
docker-compose exec bot python load_test.py --mode db --users 100

# 3. Очистить тестовые данные
docker-compose exec -e CONFIRM_CLEAR=yes bot python clear_database.py

# 4. Экстремальный тест на 500 (как при ажиотаже)
docker-compose exec bot python load_test.py --mode db --users 500

# 5. Снова очистить
docker-compose exec -e CONFIRM_CLEAR=yes bot python clear_database.py

# 6. Тест блокировок БД
docker-compose exec bot python load_test.py --mode stress --concurrent 200 --duration 20

# 7. Ещё раз очистить перед продакшеном
docker-compose exec -e CONFIRM_CLEAR=yes bot python clear_database.py
```

**Если все тесты прошли успешно → готовы к реальному ажиотажу! ✅**

## ⚠️ Что делать если тест показал плохие результаты:

### Скорость < 100 рег/сек:

```bash
# 1. Проверить индексы
cat optimize_db.sql | docker-compose exec -T db psql -U user -d new_bal_db

# 2. Увеличить shared_buffers в docker-compose.yml
# Было: 512MB → Стало: 1GB

# 3. Перезапустить
docker-compose down
docker-compose up -d
```

### p99 > 1000ms:

```bash
# 1. Уменьшить количество реплик бота (меньше конкуренции за БД)
docker-compose up -d --scale bot=2  # Вместо 3

# 2. Добавить PgBouncer (connection pooling)
# См. EXTREME_LOAD_OPTIMIZATION.md
```

### Ошибки подключения:

```bash
# Увеличить max_connections в PostgreSQL
# docker-compose.yml, строка 18: было 500 → стало 1000
```
